# 추출 결과 검수

## 원칙

자동 추출은 **확정 사실이 아니라 후보**다. 검수는 후보를 `confirmed`/`edited`/
`rejected`로 바꾸는 일이며, 판단 근거는 언제나 원문이다. 작품에 대한 사전 지식으로
확정하지 않는다 — 원문 근거로 확인할 수 없으면 확정하지 않는다.

## 절차

1. 결정적 리포트를 먼저 뽑는다. 눈으로 훑지 않는다.

   ```powershell
   node --no-warnings scripts/audit_report.mjs --doc gamja --severity error
   node --no-warnings scripts/audit_report.mjs --doc gamja --code polarity
   node --no-warnings scripts/audit_report.mjs --json
   ```

2. `/check` 화면을 연다. 위반 배지가 붙은 항목이 목록 위로 온다.
3. 아래 우선순위로 처리한다.
   1. `scope` 오류 — 근거 offset이 단락 밖. 데이터가 깨진 것이므로 즉시 제외한다.
   2. `actor` 오류 — 사건 참여 인물의 언급이 그 단락에 없다. 원문을 보고
      (a) 별칭 누락이면 인물 별칭을 고치고, (b) 실제로 없으면 사건에서 뺀다.
   3. `state`/`temporal` 오류 — 상태·구간 모순. 대개 인물 병합이 필요한 신호다.
   4. `polarity` 확인 — 부정문에서 뽑힌 행동. 반대 의미면 제외한다.
   5. 나머지는 신뢰도 낮은 순.
4. 편집 후 **재계산**을 눌러 상태·관계·감사를 다시 만든다.
5. 결과를 저장한다(현재 결과 저장). 저장하지 않으면 메모리에만 남는다.

## 제약 위반 다섯 축

| 코드 | 뜻 | 전형적 원인 |
| --- | --- | --- |
| `actor` | 사건 참여 인물의 mention이 그 단락에 없다 | 별칭 목록에 조사형이 빠짐, 동일 인물이 둘로 갈라짐 |
| `scope` | 근거 offset이 단락 범위 밖 | 병합 과정의 앵커 오류. 데이터 손상 |
| `polarity` | 부정문에서 실제 행동 사건을 추출 | "…하지 않았다"를 행동으로 오인 |
| `state` | 같은 시점에 모순된 상태 / 미등장 장소를 현재 위치로 지목 | 장소 첫 등장보다 이른 상태, 인물 중복 |
| `temporal` | 상태 구간이 겹치거나 첫 등장보다 앞선다 | 인물 병합 필요, LLM 상태 변화의 시점 오류 |

`error`는 데이터 계약 위반이므로 고치거나 제외한다. `warn`(polarity)은 휴리스틱
의심이므로 **원문을 읽고** 판단한다. warn을 일괄 제외하지 않는다.

## 엔티티 경계 판정 기준

`doc/README.md` §4(별칭 매칭 — 단일 규칙)가 기준이다. 자주 쓰는 것만 옮기면:

- 인물: 명시적 사람 지칭어(`아내`, `남편`, `마나님`, `선생`…)를 우선한다. 일반 이름
  후보는 반복 출현 + 주격/화제 조사 + 사람 행위 문맥이 함께 있어야 한다.
- 장소: 공백 없는 핵심 명사만. `불길`, `시집`, `징역`처럼 장소 접미사와 철자가
  겹치는 일반어는 제외한다.
- 오탐 금지 목록(회귀 테스트가 지킨다): `모양`, `조밥`, `마음`, `얼굴`, `머리`,
  `소리`, `활극`, `바구니`, `불길`, `징역`, `들어가게`.

이 목록에 해당하는 항목이 살아 있으면 그것부터 `rejected`로 바꾼다.

## 하지 말 것

- 자동 일괄 확정. `confirmed`는 원문 근거를 하나씩 본 결과여야 한다.
- 원문에 없는 인물·사건 추가. 수동 사건은 원문에 근거가 있을 때만 만든다.
- 위반이 0이 될 때까지 데이터를 지우는 것. 누락보다 오탐이 나쁘지만, 근거 있는
  항목을 위반 수치 때문에 지우면 안 된다.
