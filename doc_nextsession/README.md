## 1. 동적 seed의 인물 과다 생성 (최우선)

「감자」를 외부 문서처럼 분석하면 인물이 14명 나온다.

```text
복녀  서방  남편  부처  나  여인들  감독  색시  장인  여편네  중국인들  신부  아버지  노인
```

골든셋 기준 `characters P=0.429 R=0.667`이다. 두 가지가 겹쳐 있다.

- **분열**: `서방`·`남편`은 같은 인물(복녀의 남편)이고, `여인들`·`여편네`도 같은 집단이다.
  정적 seed에서는 하나로 묶여 있다.
- **과다**: `부처`, `나`, `신부`, `아버지`, `노인`은 인물이 아니거나 일회성 보통명사다.
  `왕 서방`은 오히려 누락된다(골든셋이 지적하는 유일한 필수 인물 누락).

이는 "오탐보다 누락을 택한다"는 원칙과 정면으로 어긋난다. 시작점은
`analyzer.js`의 `buildDocumentCharacterSeeds()`이고, 판정 근거(반복 출현·주격 조사·
사람 행위 문맥)의 임계값과 사람 지칭어 목록이 실제 후보에 어떻게 작용하는지부터 계측해야
한다. 손대기 전에 현재 출력을 스냅샷으로 고정하고, `npm run eval`의 P/R과
오탐 금지 목록을 회귀 기준으로 삼는다.

## 2. `koreanCaseAliases()`의 조사형 열거 제거

동적 seed는 별칭에 조사형을 기계적으로 붙인다.

```text
복녀[복녀 | 복녀은 | 복녀는]   서방[서방 | 서방은 | 서방는]
```

받침을 보지 않으므로 `복녀은`·`서방는`처럼 성립하지 않는 형태가 절반이다. 무해하지만
죽은 무게이고, **`aliasPattern()`이 조사를 규칙으로 처리하게 된 지금은 역할이 겹친다.**
정적 seed의 `복녀는`, `나에게` 같은 열거 항목도 마찬가지다.

제거하면 별칭 목록이 짧아지고 매칭도 빨라진다. 다만 `mention.text`의 표층형이
`복녀는` → `복녀`로 바뀌므로 화면 강조 범위와 QA 픽스처를 함께 확인해야 한다.
계약 필드가 바뀌는 것은 아니다.

## 3. 인물 병합·분리 검수 UI

1번을 자동으로 완전히 풀 수는 없다. `서방`과 `남편`이 같은 인물인지는 원문을 읽어야
안다. 검수 화면에서 두 인물을 합치고 별칭을 옮기는 조작이 필요하다.

- 병합은 mention을 옮기고 `first_segment_id`·`valid_from`을 다시 계산해야 한다.
- 상태·관계는 `refreshNarrativeTime()`으로 재계산된다.
- 자동 제안은 `suggested`로만 노출하고 확정은 사람이 한다.

## 4. `polarity` 경고의 정밀도

「날개」에서 78건이 뜬다. 현재는 부정 표현이 문장 어디에 있든 경고하므로 작용 범위를
보지 않는다. 사건 근거 span과 부정 표현의 거리·절 경계를 보면 줄일 수 있다.
`error`가 아니라 `warn`이므로 급하지는 않지만, 78건이면 사실상 아무도 보지 않는다.

## 5. LLM 채널 실측

이번 작업은 전부 LLM 없이 검증했다. 다음은 로컬 Ollama가 있는 환경에서 해야 한다.

```powershell
npm run eval -- --live qwen3.5:4b
```

확인할 것: 장면 파이프라인의 실제 recall, `scenes_failed` 발생률, 청크당 소요 시간,
관계 pass가 인물 간 관계를 실제로 만들어 내는지. 규칙 채널은 인물 간 관계를 만들지
않으므로 이 축은 LLM 채널이 유일한 공급원이다.

what-if도 마찬가지다. 실모델에서 `detectCanonLeak()`이 얼마나 걸리는지, 4B 모델이
분기 시점 상태와 모순되지 않는 전개를 내는지 아직 모른다.

## 6. 평가셋 확장

골든셋이 「감자」 한 편뿐이다. 공개도메인 단편 2~3편을 `texts/`에 추가하고
`/check`에서 확정한 목록을 골든셋으로 고정한다. 모델 출력을 정답으로 넣으면 그 뒤의
모든 측정이 무의미해진다.

as-of QA 문항도 13개뿐이다. 특히 "거부해야 하는" 케이스가 적다.

## 작업할 때 지킬 것

`AGENTS.md`가 짧은 판이고, 아래는 이번 작업에서 실제로 문제를 막았거나 드러낸 것들이다.

1. **스포일러 판정을 새로 쓰지 않는다.** 시점 비교가 필요하면 `src/core/asof.js`를 부른다.
   `index <= currentSegment`를 다른 곳에 쓰는 순간 판정이 두 벌이 되고, 어긋난 지점이
   곧 누출이다.
2. **별칭 매칭도 마찬가지다.** `aliasPattern()` 하나만 쓴다. 예전에 세 채널이 각자
   규칙을 쓴 결과가 「날개」 32건, 「감자」 22건의 `actor` 위반이었다.
3. **추출 규칙을 바꾸면 먼저 스냅샷을 뜬다.** 코퍼스 전체의 엔티티·mention 수가 바뀌므로
   `npm run eval`, `npm run eval:qa`, `npm run audit`을 전후로 비교하고, 첫 등장 단락이
   바뀐 항목은 **원문으로 직접 확인한 뒤에** QA 픽스처를 고친다. 픽스처를 먼저 고치면
   회귀를 정답으로 만들어 버린다.
4. **감사 위반을 데이터를 지워서 없애지 않는다.** `error`는 계약 위반이므로 원인을
   고치고, `warn`은 원문을 보고 판단한다.
5. **생성물과 사실을 섞지 않는다.** what-if 결과는 `branches[]`에만 두고 원문 근거를
   붙이지 않는다.
6. **`mcp/`에 분석 규칙을 두지 않는다.** 어댑터로만 유지한다.
7. 빌드도 린터도 없으므로 import 누락은 런타임에야 드러난다. `npm test`가
   `module_wiring.test.mjs`로 잡아 주지만, 뷰 모듈을 만지면 한 번 더 확인한다.
