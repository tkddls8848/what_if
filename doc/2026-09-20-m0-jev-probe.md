# M0 — `typesafe/jev` 요청/응답 스키마 실물 확인

Created: 2026-09-20
Status: **M0 완료. 게이트웨이 충전 후 2026-09-20 라이브로 뚫렸다.**
M1 구현 완료, M2 측정 완료 — **네 지표 중 하나(전환 감지 recall) 미달.** 6절 참고.

[`2026-09-20-scene-director-jev-design.md`](2026-09-20-scene-director-jev-design.md) 4절과
12절 M0의 기록이다. 그 문서는 "M0이 끝나기 전에는 5절 이하를 구현하지 않는다"고
못박았으므로, 이 문서가 그 게이트의 답이다.

## 1. 한 문장

Jev는 **실재하고, 이 계정에서 돌고, 한국어를 읽는다.** 다만 설계 문서 4절의 전제 —
"기존 자격증명을 그대로 쓰면 되고 **새 키도 새 의존성도 없다**" — 는 절반만 맞았다.
**새 키는 정말 필요 없었지만**(기존 `CF_ACCOUNT_ID`/`CF_API_TOKEN` 그대로다),
Jev는 Workers AI 무료 Neuron 할당 **밖**이라 게이트웨이에 돈을 넣어야 했고,
호출 경로도 이 저장소가 쓰는 `ai/run/{model}`이 아니다.

> **2026-09-20 후속:** 게이트웨이에 크레딧을 충전한 뒤 같은 요청이 **200**을 돌려줬다.
> 아래 2-3의 402는 그 시점의 기록으로 남긴다. 실물 응답 스키마는 3절, 한국어
> 정확도와 M2 측정 결과는 6절에 있다.

## 2. 실제로 주고받은 것

계정은 `.env`의 `CF_ACCOUNT_ID`, 토큰은 `CF_API_TOKEN`(Workers AI Read/Edit).
아래 `{acct}`는 그 계정 id다. 모든 호출은 `Authorization: Bearer <토큰>`.

### 2-1. 카탈로그에 없다

```
GET /client/v4/accounts/{acct}/ai/models/search?search=jev       → 200, result 0건
GET /client/v4/accounts/{acct}/ai/models/search?search=typesafe  → 200, result 0건
```

페이지네이션으로 전체를 받아도 **65개 전부가 `@cf/…`**이고 typesafe 벤더는 없다.
즉 이 계정의 Workers AI 카탈로그에 Jev는 올라와 있지 않다.

### 2-2. `ai/run/typesafe/jev`는 라우트 자체가 없다

설계 문서 4절이 추정한 경로다. 바디 모양(`input` 래핑/평면)과 `@cf/` 접두를
바꿔 네 번 시도했고 전부 같은 답이다.

```
POST /client/v4/accounts/{acct}/ai/run/typesafe/jev
POST /client/v4/accounts/{acct}/ai/run/@cf/typesafe/jev
  → 400 {"success":false,"errors":[{"code":7000,"message":"No route for that URI"}]}
```

프로브가 틀린 게 아니다 — 같은 harness로 같은 자리에 기존 모델을 넣으면 돈다.

```
POST /client/v4/accounts/{acct}/ai/run/@cf/meta/llama-3.3-70b-instruct-fp8-fast
  body: {"messages":[{"role":"user","content":"say OK"}],"max_tokens":5,"stream":false}
  → 200 {"result":{"choices":[{"message":{"content":"OK",…}}],…}}
```

### 2-3. 진짜 경로는 `ai/run`(모델을 바디에 싣는다)이고, 거기서 **과금**에 막힌다

```
POST /client/v4/accounts/{acct}/ai/run
  body: {
    "model": "typesafe/jev",
    "input": {
      "state": { "previous_scene": "3학년 2반 교실 / 밤 / 비",
                 "narration": "그는 교실 문을 열고 복도로 나섰다. …" },
      "questions": {
        "place": { "type": "choice",
                   "instructions": "이번 턴 서술이 벌어지는 장소를 고르시오.",
                   "criteria": { "classroom_3_2": "3학년 2반 교실",
                                 "hallway": "복도", "front_gate": "정문 앞" } }
      }
    }
  }
  → 402 {"errors":[{"message":"Insufficient balance; add money to your gateway or use BYOK",
                    "code":2021}],"success":false}
```

**402는 "모델이 없다"가 아니라 "돈이 없다"이다.** 이 구분이 M0의 핵심이라
대조 실험으로 확정했다.

| 대조 | 요청 | 결과 | 읽는 법 |
| --- | --- | --- | --- |
| 가짜 모델 | `model: "typesafe/definitely-not-a-real-model-xyz"` | **404** `7003 Model not found` | 모델 검증이 과금 검사보다 **먼저** 돈다 |
| 가짜 벤더 | `model: "nosuchvendor/nosuchmodel"` | **404** `7003 Model not found` | 위와 같다 |
| 기존 모델 | `model: "@cf/meta/llama-3.3-70b…"` + `messages` | **400** `7000 Invalid request body: input` | 이 경로는 `input` 계약이다 — `ai/run/{model}`과 **다른 계약** |

가짜 이름이 404로 떨어지는데 `typesafe/jev`가 402까지 갔다는 것은,
**Cloudflare가 이 모델 이름을 알고 있고 라우팅했으며 과금 단계에서 멈췄다**는
뜻이다. 모델은 있다.

### 2-4. 참고 — `ai/v1/responses`는 Jev의 자리가 아니다

```
POST /client/v4/accounts/{acct}/ai/v1/responses  → 400 ZodError
  "path":["body","input"], "expected":"string" / "array", "received":"object"
```

OpenAI Responses 모양을 받는 경로라 `input`이 문자열이나 배열이어야 한다.
Jev의 `input.state`/`input.questions` 객체는 여기 맞지 않는다.

## 3. 스키마 — 실물로 확인했다

크레딧 충전 후 같은 요청이 200을 돌려줬다. **응답 봉투가 문서와 다르다** —
문서는 가장 안쪽 모양만 적어 두는데, Cloudflare를 거치면 두 겹이 더 붙는다.

```json
{ "success": true, "errors": [], "messages": [],
  "result": {
    "state": "Completed",
    "gatewayMetadata": { "keySource": "Unified" },
    "result": {
      "model": "jev-1.13.0",
      "answers": {
        "place": { "type": "choice", "choice": "hallway",
                   "probabilities": { "classroom_3_2": 0.03, "hallway": 0.97, "front_gate": 0 },
                   "confidence": 0.96 } },
      "usage": { "input_tokens": 407, "output_tokens": 47 } } } }
```

`answers`는 `result.result.answers`에 있다. `src/llm/jev.js`의 `unwrap()`이 세 깊이를
모두 열어 보는 이유다 — 봉투가 또 바뀌어도 조용히 깨지지 않는다.

요청은 문서 그대로가 맞았다.

```json
{ "model": "typesafe/jev",
  "input": {
    "state": { "previous_scene": {...}, "narration": "..." },
    "questions": {
      "<이름>": { "type": "choice|noul|score", "instructions": "...", "criteria": {...} } } } }
```

- `choice`의 `criteria`는 **객체** `{ "선택지 키": "설명" }` — 설계 5절의
  `locations[].id` → `ko`가 그대로 들어맞는다.
- **한 호출에 질문 여러 개**를 `questions`의 키로 싣는 것이 된다. 장소·시간·날씨를
  한 번에 묻는 6절의 배선이 실제로 성립한다.
- **한국어 `state`·한국어 선택지 키가 동작한다.** 시간대·날씨는 `"밤"`, `"비"` 같은
  한국어 낱말을 키로 그대로 쓴다.
- `gatewayMetadata.keySource: "Unified"` — 충전한 통합 크레딧으로 계산됐다는 뜻이다
  (BYOK가 아니다).

단가: 한 턴(질문 3개, 장소 4~5곳)에 **입력 약 620~650 토큰, 출력 약 125 토큰**이다.
출력은 무료이고 입력만 과금된다.

## 4. 과금 — 무료가 아니다

`typesafe/jev`는 2026-08의 Workers AI ↔ AI Gateway 통합 과금에 속한 **서드파티
모델**이다. 무료 Neuron 할당으로는 부르지 못하고 둘 중 하나가 필요하다.

| 길 | 필요한 것 | 결과 |
| --- | --- | --- |
| **A. 게이트웨이 선불 크레딧** | AI Gateway에 돈을 넣는다 | **이 길로 갔다.** 새 키 없음 |
| B. BYOK | TypeSafe 제공자 키를 게이트웨이에 등록 | 안 썼다. Jev는 early access라 키 발급 자체가 불확실하다 |

A로 충전한 뒤 응답의 `gatewayMetadata.keySource`가 `"Unified"`로 온다 — 통합
크레딧으로 계산됐다는 뜻이다. **새 환경변수는 필요 없었다.** 기존
`CF_ACCOUNT_ID`/`CF_API_TOKEN`이 그대로 인증한다.

### 4-1. AI Gateway 경유는 선택 사항이다

`CF_GATEWAY_ID`를 채우면 같은 바디가 게이트웨이 데이터 플레인으로 나간다
(`https://gateway.ai.cloudflare.com/v1/{acct}/{gw}/ai/run`). 로그·캐시·레이트리밋이
거기 붙는다. 비워 두면 v4 통합 엔드포인트로 직접 간다 — **둘은 URL과 헤더만
다르고 바디·응답 계약이 같다.**

이 계정에서는 아직 게이트웨이를 안 만들었다. 확인한 것 둘.

- 데이터 플레인은 **없는 게이트웨이 이름에 404가 아니라 401**(`AiGatewayError`
  code 2009)을 낸다. 계정에 그 게이트웨이가 있는지를 노출하지 않으려는 것이다.
  `default`를 포함해 어떤 이름으로도, 어떤 헤더 조합으로도 같은 401이었다.
- 지금 `CF_API_TOKEN`에는 **AI Gateway 권한이 없다** — 제어 플레인
  (`GET/POST /accounts/{id}/ai-gateway/gateways`)이 403 `10000 Authentication error`다.
  게이트웨이를 쓰려면 대시보드에서 만들거나 토큰에 AI Gateway Read/Edit를 더해야 한다.

그래서 401을 토큰 문제로 뭉뚱그리지 않는다 — 게이트웨이를 거쳐 보냈다는 것은
우리 설정으로 이미 아는 사실이라, `src/llm/jev.js`가 그 경우 "게이트웨이 이름을
확인하라"고 따로 안내한다. 401 본문은 여전히 읽지 않는다(토큰 노출 우려).

## 5. M2 — 골든셋 30턴 측정 결과

`scripts/eval_scene_director.mjs`와 `tests/fixtures/golden/scene_director.golden.json`
(demo 15턴 + lighthouse 15턴). 설계 10절의 네 지표다.

| 지표 | 기준 | 결과 | |
| --- | --- | --- | --- |
| 전환 감지 recall | ≥ 0.90 | **0.478** (임계 0.7) / **0.652** (임계 0.5) | **미달** |
| 전환 감지 precision | ≥ 0.85 | **1.000** | 통과 |
| 장소 정확도 | ≥ 0.95 | **1.000** | 통과 |
| 재방문 캐시 히트 | 100% | **1.000** | 통과 |

축별 단독 정확도: 장소 0.933, 시간 0.933, 날씨 0.933. 세 축 동시 정답 0.80.

### 5-1. 한국어는 문제가 아니었다

설계 10절이 "이 설계의 최대 미검증 요소"로 꼽은 한국어 정확도는 **막히지 않았다.**
한국어 서술을 읽고 한국어 시간대·날씨 낱말을 고르는 일을 축당 93%로 해낸다.

### 5-2. 임계 튜닝으로는 recall 기준을 못 넘는다

저장된 리포트의 원시 확신도로 임계를 오프라인 스윕했다(추가 호출 없음).

```
임계   전환 recall  전환 precision  장소 정확도
0.70   0.478        1.000           1.000
0.60   0.652        1.000           1.000
0.50   0.652        1.000           1.000
0.35   0.739        1.000           1.000
0.25   0.826        1.000           1.000
0.00   0.826        1.000           1.000   <- 임계를 아예 없앤 상한
```

**임계를 완전히 없애도 recall 상한이 0.826이다.** 병목은 게이트가 아니라 모델의
답 자체다 — 놓친 턴들에서 Jev는 "아직 직전 장소에 있다"고 답한다. 축별로 다른
임계를 두는 안(설계 13절 열린 질문 2)도 전수 조사했고, 네 기준을 동시에 만족하는
조합은 **없었다**.

측정 중에 지시문을 한 번 고쳤다(이동 중 서술에서 출발지를 고르는 경향 때문에
"이 서술이 **끝나는 시점에** 인물이 있는 장소"로 명시). 그 한 번으로 장소 단독
정확도가 0.833 → 0.933, recall 상한이 0.696 → 0.826으로 올랐다. 30턴짜리
골든셋에 더 맞추는 것은 과적합이라 거기서 멈췄다.

### 5-3. 그래서 기본 임계를 0.7에서 0.5로 내렸다

설계 6절이 "임계값은 M2의 골든셋으로 정한다(초기값 0.7)"고 했으므로 정한 값이다.
근거는 위 표의 한 줄 — **이 구간에서 precision과 장소 정확도가 임계와 무관하게
1.000이다.** 임계를 낮춰도 틀린 그림이 늘지 않았으니 0.7을 지킬 근거가 없다.
0으로 내리지 않은 이유는 "모르면 바꾸지 않는다"는 안전장치 자체를 없애지 않기
위해서다 — FP가 0인 것은 30턴에서 관측된 사실이지 보장이 아니다.

운영에서는 `SCENE_CONFIDENCE`로 덮어쓴다.

### 5-4. 미달의 성격 — 틀린 그림이 아니라 낡은 그림이다

이 미달을 어떻게 읽을지가 후퇴 판단의 핵심이다.

- precision 1.000, 장소 정확도 1.000 — **그리기로 한 턴에서는 한 번도 틀리지
  않았다.** 잘못된 배경이 뜨는 일은 관측되지 않았다.
- 미달한 recall의 실패 모드는 "장면이 바뀐 걸 못 알아채고 **직전 그림을 그대로
  둔다**"이다.

설계 6절이 안전한 기본값으로 고른 것이 정확히 그 실패다("잘못 바꾸면 틀린 그림이
걸리고, 안 바꾸면 조금 낡은 그림이 걸린다. 후자가 덜 나쁘다"). 즉 시스템은 설계한
대로 실패하고 있고, 미달한 것은 그 실패의 **빈도**다.

### 5-5. 남은 선택지

설계 10절은 "M2에서 기준 미달이면 이 설계를 접고 로컬 Ollama enum으로 후퇴한다"고
적었다. 다만 그 후퇴안이 고치는 것은 **판정기**인데, 여기서 미달한 것은 판정기의
정의역이나 확률 보정이 아니라 "이동을 알아채는" 능력이다 — 후퇴안이 그걸 더 잘
한다는 근거는 아직 없다. 판단 재료 넷을 적어 둔다.

1. **골든셋을 넓힌다.** 30턴은 recall을 0.03 단위로밖에 못 잰다(전환 23건).
   기준 미달이 실제 실력인지 표본 노이즈인지 지금은 못 가른다.
2. **기준을 다시 본다.** 0.90은 설계 시점의 희망치였다. 5-4를 받아들이면
   "recall 0.83 / precision 1.0"은 배경 그림 기능으로 쓸 만하다.
3. **질문을 하나 더 둔다.** "직전 장면에서 이동했는가"를 `Noul`로 따로 묻는 안.
   설계 6절이 중복이라고 뺀 질문이지만, 지금 놓치는 것이 정확히 그 판단이다.
4. **후퇴안(로컬 Ollama enum)으로 간다.** 단, 확률이 없어져 5-3의 임계 규칙을
   다른 수단으로 다시 설계해야 한다.

## 6. 재현

M2 측정은 저장소에 있다.

```powershell
node scripts/eval_scene_director.mjs --dry     # 호출 없이 골든셋만 점검
node scripts/eval_scene_director.mjs           # 실제 호출. 30턴에 입력 약 2만 토큰
node scripts/eval_scene_director.mjs --threshold 0.35 --out report.json
```

2절의 경로 프로브는 일회성이라 남기지 않았다. 재현하려면 그 요청을 그대로 보내면
된다 — `.env`의 자격증명과 `fetch`면 충분하고, 새 의존성은 필요 없다.
