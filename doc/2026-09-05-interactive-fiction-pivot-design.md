## 1. 무엇을 만드는가

기존 작품(서브컬처)의 캐릭터와 세계관을 재료로, **장면 서술 중심 + 자유 입력**
방식의 인터랙티브 소설을 생성하는 로컬 앱.

한 턴은 이렇게 생겼다.

```
[서술] 복도 끝에서 발소리가 멈췄다. 아스카는 문틀에 손을 짚은 채
       너를 돌아보지 않았다. "……왜 따라왔어."

[너의 행동을 쓰거나, 아래에서 고르세요]
  1. 아무 말 없이 옆에 선다
  2. "혼자 두면 또 무리할 거잖아"
  3. 돌아서서 그대로 나간다
  >_ ________________________________
```

기본은 3인칭 장면 서술이고, 사용자는 행동을 직접 서술하거나 추천 선택지를 고른다.
제타의 스토리 모드에 가깝고, 순수 채팅 롤플레이도 순수 선택지 픽션도 아니다.

**단독 사용 파일럿이다.** 계정·과금·모더레이션·다중 사용자는 범위 밖이고, 저작권
게이트도 두지 않는다(3-3절).

### 왜 이 저장소를 피보팅하는가

제타·크랙류의 알려진 약점은 **긴 세션에서 캐릭터가 무너지는 것**이다. 20~30턴이
넘으면 설정을 잊고, 위치가 모순되고, 이미 죽은 인물이 다시 나온다. 원인은 컨텍스트에
"지금 상황"의 구조화된 표상이 없고 대화 로그와 요약 문장만 있기 때문이다.

이 저장소에는 그 표상을 만들고 검사하는 물건이 이미 있다 — `core/asof.js`의 KNOWN/TRUE
판정, `core/audit.js`의 5축 제약 감사, `Event`/`CharacterState` 스키마. 좌표를
segment index에서 turn index로 바꾸면 그대로 동작한다. **이 재사용이 피보팅의 유일한
정당화이며, 이것을 버리는 설계는 재작성이지 피보팅이 아니다.**

### 2-3. 테스트

`tests/` 161건 중 규칙 추출·주석·묘사에 묶인 것들(`analyzer.test.mjs`,
`annotations.test.mjs`, `descriptions.test.mjs`, `asof_qa.test.mjs`의 원문 QA)은
함께 죽는다. `asof.test.mjs`·`audit.test.mjs`·`query.test.mjs`·`recap.test.mjs`·
`whatif.test.mjs`는 좌표 교체에 맞춰 fixture만 바꾼다.

**M1에서 테스트를 통과 상태로 유지하지 않는다.** 죽일 모듈의 테스트를 살려두면
피보팅이 아니라 두 제품을 동시에 유지하는 일이 된다. M3 완료 시점에 새 기준으로
전부 초록이 되는 것을 완료 조건으로 잡는다(11절).

## 3. 모델 채널

### 3-1. 두 종류의 호출

> 2026-09-20 현재 **세 종류**다 — 아래 둘에 **장면 판정**(TypeSafe Jev, 닫힌 선택지)이
> 더해졌다. 그것도 같은 이유로 갈려 나왔다: 서술자에게 기준을 보여주면 이야기가 그
> 기준에 맞춰진다. `doc/README.md` 3-1절 참고.

한 턴은 성격이 완전히 다른 두 호출로 이뤄진다.

| | ① 서술 생성 | ② 상태 추출 |
| --- | --- | --- |
| 무엇 | 장면 산문 + 선택지 3개 | 그 턴의 `event_frames`, `state_changes` |
| 품질 요구 | 제품 그 자체 | 스키마만 맞으면 됨 |
| 출력 형식 | 자유 텍스트 | JSON Schema 강제 |
| 스트리밍 | **필수** (체감 지연) | 불필요 |
| 담당 | Cloudflare Workers AI 70B | 로컬 Ollama 4B |

**이 분리는 선택이 아니라 강제다.** Workers AI의 JSON 모드는 스트리밍을 지원하지
않는다. 한 호출로 산문과 구조화 데이터를 같이 받으려면 스트리밍을 포기해야 하고,
그러면 매 턴 수 초의 백지 대기가 생긴다.

②를 서술 스트리밍이 끝난 뒤 **비동기로** 돌리므로 체감 지연은 0이다.

### 3-2. Cloudflare Workers AI 계약

Workers 배포 없이 Node에서 REST로 직접 호출한다.

```
POST https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai/run/{MODEL}
Authorization: Bearer {API_TOKEN}
```

API 토큰은 `Workers AI - Read`와 `Workers AI - Edit` 두 권한이 필요하다.
`CF_ACCOUNT_ID`, `CF_API_TOKEN` 환경변수로 받고 저장소에 넣지 않는다.

구조화 출력은 OpenAI 호환이다.

```json
{ "response_format": { "type": "json_schema", "json_schema": { } } }
```

JSON 모드 지원 모델은 9종이며 `@cf/meta/llama-3.3-70b-instruct-fp8-fast`가 포함된다.
다만 이 앱에서 구조화 출력은 로컬이 담당하므로 실제로 쓰지 않는다 — 로컬 Ollama가
죽었을 때의 폴백 경로로만 남긴다.

### 3-3. 예산

무료 할당은 **하루 10,000 Neurons**이고 초과분은 1,000 Neurons당 $0.011다.
`@cf/meta/llama-3.3-70b-instruct-fp8-fast`는 100만 토큰당 입력 26,668 / 출력
204,805 Neurons다.

표준 시나리오(서술 약 600자)의 프롬프트 구성은 이렇다. 5절의 기억층과 같은 표다.

| 구성 | 토큰 |
| --- | ---: |
| 고정 프리픽스 — 캐릭터 카드 1~2장 + 세계관 규칙 | 700 |
| 상태 블록 | 300 |
| 요약 체인 | 400 |
| RAG 조각 3~5개 | 600 |
| 최근 3턴 원문 | 1,650 |
| **입력 합계** | **3,650** |
| 출력 — 서술 + 선택지 3개 | 500 |

| 시나리오 | 입력 | 출력 | Neurons/턴 | 무료 한도 내 턴 수 |
| --- | ---: | ---: | ---: | ---: |
| 짧은 서술 (약 400자) | 2,900 | 350 | 149 | **67** |
| 표준 (약 600자) | 3,650 | 500 | 200 | **50** |
| 긴 서술 (약 1,000자) | 4,800 | 800 | 292 | **34** |

세 가지가 여기서 따라 나온다.

**출력이 비용의 48~56%다.** 서술 길이가 가장 큰 단일 레버이므로 `max_tokens`를 세션
설정으로 노출하고, 남은 Neurons에 따라 자동으로 조이는 정책을 M4에서 넣는다.

**입력도 무시할 수 없다.** 최근 턴 원문이 입력의 45%를 차지한다. 그래서 단기 기억을
6턴이 아니라 **3턴**으로 잡았다(5절) — 6턴을 원문으로 보관하면 그것만 3,200토큰이라
턴당 Neurons가 200 → 242로 오르고 하루 41턴으로 떨어진다. 보관 턴 수는 예산 레버이지
품질 상수가 아니며, 잃는 문맥은 요약 체인과 상태 블록이 받는다.

**8B로 내려도 소용이 없다.** `llama-3.1-8b-instruct`는 입력 25,608 / 출력 75,147로
입력 단가가 70B와 거의 같다. 표준 시나리오에서 200 → 131 Neurons, 절감은 35%뿐인데
한국어 롤플레이 서술 품질 차이는 그보다 훨씬 크다. **서술 모델은 70B로 고정한다.**
(참고: `mistral-7b-instruct-v0.1`은 10,000/17,300으로 압도적으로 싸지만 한국어가
쓸 만하지 않다. `gemma-3-12b-it` 31,371/50,560은 폴백 후보로만 기록해 둔다.)

**RAG는 비용 절감 장치가 아니다.** 입력 비중이 작아서 절감폭이 미미하다. RAG는
"설정 문서 전체를 프롬프트에 넣기"의 대안이지 "아무것도 안 넣기"의 대안이 아니며,
전체 투입은 컨텍스트 한도상 애초에 불가능하다. **RAG의 값어치는 예산이 아니라 설정
정확도다.**

미확인: Workers AI 카탈로그에는 DeepSeek V4 Pro(1M ctx), GLM-5.3, Kimi K2.7,
Nemotron 3 120B, Llama 4 Scout 등 더 큰 모델이 있으나 Neuron 단가를 확인하지 않았다.
M1에서 어댑터가 모델 id를 설정값으로 받으므로, 단가 확인 후 교체는 한 줄이다.

### 3-4. 저작권

**파일럿이므로 게이트를 두지 않는다.** `rights` 필드와 MCP의 원문 배포 차단을
걷어낸다. 설정 자료 원본도 폐기하지 않고 보관해 RAG 인덱스로 쓴다.

`detectCanonLeak()`은 **품질 경고로 격하**한다. 서브컬처 롤플레이에서는 원작 명대사
재현이 오히려 플러스일 수 있으므로 차단하지 않고 표시만 한다. 이 함수를 남기는 실제
이유는 다른 데 있다 — 모델이 생성 대신 설정 자료를 그대로 복사해 오는 실패 모드를
검출한다.

배포·공개는 범위 밖이다. 공개하게 되면 이 절 전체를 다시 쓴다.

## 4. 턴 사이클

```
사용자 입력 (자유 서술 또는 추천 선택지)
  │
  ├─ 프롬프트 조립 (5절)
  │     캐릭터 카드 + 세계관 규칙 + [상태 블록] + RAG 조각 + 최근 3턴 + 요약 체인
  │
  ├─ ① Cloudflare 70B — 스트리밍 ON, JSON OFF
  │     → 장면 서술 + 선택지 3개
  │     → 화면에 즉시 스트리밍 (SSE)
  │
  └─ (서술 완료 후, 비동기)
        ② 로컬 Ollama — json_schema, 스트리밍 없음
           → event_frames[], state_changes[]
             ↓
           audit.js 검사
             ↓
           위반 있으면 → 다음 턴 프롬프트에 교정 지시문 주입
             ↓
           상태 그래프 갱신 · 8턴마다 요약 압축 트리거
```

선택지 3개는 서술과 같은 호출에서 받는다. 별도 호출로 나누면 턴당 Neurons가
1.5배가 되고, 선택지는 방금 쓴 장면의 문맥이 가장 진할 때 나와야 좋다.

②가 실패해도 턴은 성공이다. 상태 갱신만 건너뛰고 `turn.extraction_failed`에
기록한다. 로컬 모델이 없어도 앱은 동작한다 — 기존 저장소의 5원칙("LLM은 선택
채널이다")을 여기서도 유지하되, 대상이 뒤집혔다. **이제 필수는 클라우드고 선택이
로컬이다.**

## 5. 기억 4층

프롬프트는 **고정 프리픽스 + 기억 4층**이다. 이것 말고는 아무것도 들어가지 않는다.

| | 내용 | 크기 | 만드는 비용 |
| --- | --- | ---: | --- |
| 프리픽스 | 캐릭터 카드 1~2장 + 세계관 규칙·금지사항 | 700 | 0 (컴파일 시 1회) |
| 단기 | **최근 3턴** 원문 (사용자 입력 + 서술) | 1,650 | 0 |
| 중기 | 8턴마다 압축한 요약 체인 | 400 | 로컬(무료) |
| 장기 | **상태 그래프** 직렬화 | 300 | 로컬(무료) |
| 자료 | RAG로 뽑은 설정 조각 3~5개 | 600 | 로컬 임베딩(무료) |
| | **합계** | **3,650** | |

단기가 3턴인 이유는 예산이다(3-3절). 이 값은 상수가 아니라 세션 설정이며, 남은
Neurons가 적으면 자동으로 2턴까지 줄인다.

**상태 그래프 층이 이 앱의 차별점이다.** 나머지는 어느 롤플레이 앱에나 있다.

직렬화 형식은 산문이 아니라 표다. 모델이 이 블록을 서술로 착각해 베끼는 것을 막고,
토큰도 적다.

```
[현재 상황 · 12턴]
장소: 학원 옥상 (밤)
아스카   위치=옥상, 심리=경계, 신체=팔 부상, 아는것=너의 정체
너       위치=옥상, 심리=초조
관계     아스카→너: 불신(약화 중)
직전사건 E11 아스카가 팔을 다쳤다
```

`asOf(turn)`이 이 블록을 만든다. 캐릭터가 아직 모르는 사실은 여기 들어가지 않으며,
이것이 "캐릭터가 사용자만 아는 정보를 알고 말하는" 흔한 붕괴를 막는다.

RAG 층은 로컬 임베딩(`nomic-embed-text`)으로 설정 자료를 청크·색인하고, 매 턴
사용자 입력 + 최근 서술을 질의로 상위 3~5개를 뽑는다. 벡터 저장소는 도입하지 않는다 —
파일럿 규모(작품당 수백~수천 청크)에서는 메모리 내 코사인 유사도로 충분하고,
의존성 추가는 저장소의 "빌드 단계 없음" 성질을 깬다.

## 6. 데이터 계약

### 6-1. 신규 객체

| 객체 | 필드 |
| --- | --- |
| `World` | `world_id`, `title`, `source_type`, `source_url`, `setting`, `tone`, `rules[]`, `forbidden[]`, `created_at` |
| `CharacterCard` | `card_id`, `world_id`, `canonical_name`, `aliases[]`, `persona{traits[], values[], taboos[]}`, `speech{first_person, endings[], address_rules[], examples[]}`, `appearance`, `relationships[{target_card_id, kind, note}]`, `knowledge_as_of`, `source{type, url, span}`, `status`, `confidence`, `method` |
| `SourceChunk` | `chunk_id`, `world_id`, `text`, `embedding[]`, `source_url`, `char_start`, `char_end` |
| `Session` | `session_id`, `world_id`, `card_ids[]`, `pov`(1인칭 대상 카드 또는 `null`=3인칭), `opening`, `turn_count`, `summary_chain[]`, `created_at` |
| `Turn` | `turn_id`, `session_id`, `index`, `user_input`, `narration`, `choices[]`, `events[]`, `state_changes[]`, `audit{violations[]}`, `usage{model, input_tokens, output_tokens, neurons}`, `extraction_failed` |

`Session`에는 `budget` 필드를 두지 않는다. Cloudflare의 무료 할당(하루 10,000 Neurons)은
계정 단위로 하루에 한 번 초기화되는 것이지 세션 단위가 아니다. 장부를 세션마다 복사해
두면 동시에 열린 세션이 여러 개일 때 같은 할당을 각자 따로 세어 중복 집계하게 된다.
그래서 장부는 세션이 아니라 프로세스(`server.js`의 `turnBudget`)가 소유한다.

### 6-2. 재사용 객체 — 좌표만 교체

`Event`, `CharacterState`, `Relation`은 스키마를 유지하고 시간 좌표만 바꾼다.

| 필드 | 기존 | 신규 |
| --- | --- | --- |
| `segment_id` | 원문 단락 id | **삭제** |
| `turn_index` | — | **신규.** 1부터인 정수. 0은 좌표 없음 |
| `valid_from` / `valid_to` | segment index | turn index |
| `source_span` | 원문 문자 offset | **삭제** (원문이 없다) |
| `origin` | — | `"generated"` 고정 |

`source_span` 삭제는 기존 저장소의 2원칙("모든 주장은 원문 offset으로 되짚을 수
있어야 한다")을 깨는 것이다. 의도적이다 — 생성물에는 되짚을 원문이 없다. 대신
**모든 사건은 자기를 만든 턴(`turn_index`)으로 되짚인다.** 원칙은 폐기되지 않고
앵커가 바뀐다.

`Character`/`Location`은 `CharacterCard`와 세션 내 장소 레코드로 흡수된다.

### 6-3. 저장

파일럿이므로 `localStorage` 유지가 기본이다. 단, 세션이 길어지면 5MB 한도에 걸린다
(턴당 약 2KB × 서술 → 200턴이면 위험). **M4에서 세션을 서버 파일(`data/sessions/`)로
옮긴다.** RAG 인덱스는 처음부터 서버(`data/worlds/{world_id}/`)에 둔다 — 임베딩
벡터가 크고 브라우저에 둘 이유가 없다.

## 7. 캐릭터 카드 컴파일러

두 입력 경로가 같은 컴파일러로 들어간다.

| 경로 | 방식 | 비고 |
| --- | --- | --- |
| **URL 임포트** (기본) | Fandom 등 MediaWiki `/api.php?action=parse`로 본문 획득 | `wikisource.js`의 fetch 골격 재사용 |
| **붙여넣기** (폴백) | 사용자가 텍스트를 직접 붙여넣음 | 나무위키는 봇 차단이 걸려 URL 경로가 실패한다. 폴백은 형식이 아니라 필수다 |

`server/pipeline.js`의 map-reduce 골격을 그대로 쓴다.

1. 자료를 약 1,000자 청크로 분할 (`SourceChunk`로도 저장 — RAG 인덱스와 같은 물건)
2. map: 청크마다 로컬 모델 1회 호출 → 이름·별칭·성격·말투 후보
3. reduce: 이름 정규화 dedupe, 별칭 누적, 청크 2개 이상에서 확인된 것만 편입
4. 관계 pass: 병합된 cast로 1회 호출
5. 결과는 전부 `status: "suggested"` — 사람이 `/check`에서 확정

**자동 확정은 없다.** 기존 저장소의 1원칙을 유지한다. 말투(`speech.examples[]`)만은
예외적으로 원문 인용을 그대로 넣는다 — 모델이 말투를 흉내 내려면 요약이 아니라 실제
대사가 필요하다.

`knowledge_as_of`는 사람이 지정한다. "원작 몇 화 시점의 캐릭터인가"는 자료에서 자동
판정할 수 없고, 이 값이 곧 스포일러 경계다.

## 8. 제약 감사 재사용

`core/audit.js`의 5축을 새 code 집합으로 교체한다. 판정 구조(`{code, severity,
target_type, target_id, turn_index, message}`)와 "판정만 하고 고치지 않는다" 원칙은
그대로다.

| code | 판정 | 등급 | 출처 |
| --- | --- | --- | --- |
| `actor` | 서술에 등장한 인물이 그 턴에 그 장소에 있을 수 없다 | error | 기존 `actor` 개작 |
| `state` | 같은 턴에 모순된 상태 / 등장하지 않은 장소를 현재 위치로 지목 | error | 기존 그대로 |
| `temporal` | 상태 구간 역전·중첩 | error | 기존 그대로 |
| `card` | 서술이 카드의 `taboos[]` 또는 `speech` 규칙을 위반 | warn | **신규** |
| `knowledge` | 캐릭터가 `asOf`상 모르는 사실을 알고 말한다 | error | **신규** |
| `canon` | 서술이 설정 자료와 12자 이상 연속 일치 | warn | `detectCanonLeak()` 격하 |

폐기: `scope`(원문 offset 없음), `polarity`(규칙 추출 전용), `reference`(주석 폐기).

`knowledge`가 새로 생긴 축이고, 이것이 `asOf()`를 재사용하는 값어치의 절반이다.

감사 결과는 **다음 턴 프롬프트에 교정 지시문으로 주입**된다. 사용자에게는 기본적으로
보이지 않고 디버그 패널에서만 보인다 — 매 턴 경고를 띄우면 읽는 경험이 망가진다.

## 9. 모듈 경계

```text
src/core/          런타임 공용. DOM·네트워크·전역 상태 없음 (ESM)
  asof.js            turn index 기반 KNOWN/TRUE 판정
  audit.js           설정 붕괴 감사
  query.js           상태 블록 조립용 조합 질의
  recap.js           요약 체인 입력 집계
  card.js            [신규] 카드 스키마·검증·직렬화
  session.js         [신규] 세션·턴 상태 기계
  memory.js          [신규] 4층 조립과 압축 정책
  whatif.js          세션 중간 분기
  export_if.js       ink/Twee

src/llm/           [신규] 모델 어댑터 (CommonJS — 소비자가 전부 CJS다)
  adapter.js         narrate() / extract() 두 인터페이스
  cloudflare.js      Workers AI REST + SSE
  ollama.js          기존 server/ollama_client.js 이전
  embed.js           로컬 임베딩
  budget.js          Neuron 계량과 상한 정책

src/server/        Express (CommonJS)
  turn.js            [신규] 턴 오케스트레이터
  compile_card.js    [신규] 자료 → 카드
  fetch_source.js    wikisource.js 확장
  rag.js             [신규] 청크·색인·검색

src/app/           브라우저 뷰
```

의존 방향은 기존 규칙을 유지한다 — `core/`는 위를 참조하지 않는다. **`src/llm/`도
`core/`를 참조하지 않는다.** 어댑터는 프롬프트 문자열과 스키마를 받을 뿐 도메인을
모른다. 프롬프트 조립은 `core/memory.js`가, 호출은 `src/llm/`이 한다.

어댑터 인터페이스는 두 개뿐이다.

```js
narrate({ system, messages, maxTokens, onToken }) -> { text, usage }
extract({ system, prompt, schema })               -> { data, usage }
```

Cloudflare가 `narrate`, Ollama가 `extract`를 맡는 것이 기본 배치지만 인터페이스는
대칭이라 서로 교체할 수 있다. 로컬만으로 돌리는 오프라인 모드와, 로컬이 죽었을 때
클라우드 JSON 모드로 넘어가는 폴백이 모두 이 대칭에서 나온다.

## 12. 미해결과 위험

1. **로컬 4B가 대화 턴에서 상태를 정확히 뽑는가.** 기존 파이프라인은 소설 원문을
   분석했고, 대화 턴 추출은 다른 과제다. 검증되지 않았으며 M3의 주된 위험이다.
   실패하면 ②를 Cloudflare JSON 모드로 올려야 하고, 그러면 턴당 Neurons가 1.5~2배가
   되어 하루 30턴 수준으로 떨어진다.
2. **하루 50턴이 실사용에 충분한가.** 한 세션 30턴이면 하루 두 세션이 안 된다.
   M1에서 실제로 돌려 보고 부족하면 유료 전환(1,000 Neurons당 $0.011 — 50턴 추가에
   약 $0.11)을 검토한다. 파일럿 규모에서는 이 금액이 문제가 아니므로, 무료 한도는
   설계 제약이 아니라 **기본값**으로만 취급한다.
3. **나무위키 fetch 실패율.** 붙여넣기 폴백이 있으므로 치명적이지 않지만, 주요
   출처가 URL로 안 들어오면 M2의 체감 가치가 크게 떨어진다.
4. **Workers AI 대형 모델 단가 미확인.** DeepSeek V4 Pro 등이 70B보다 싸거나 비슷하면
   서술 품질이 크게 오른다. M1에서 확인한다.
5. **한국어 토큰 추정치가 어림값이다.** 3-3절 표는 600자 ≈ 500토큰 가정이며 실측이
   아니다. M4의 계량기가 실제 `usage`를 기록하면 이 표를 실측으로 교체한다.
